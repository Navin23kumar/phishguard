SECTION 2
Abstract - Project Summary & Outcome

• Proposed Idea:

Build a lightweight, offline desktop scanner in pure C to detect fake phishing emails without requiring heavy cloud AI models or external Python libraries.

• Problem Addressed:

Attackers deceive students and non-technical users using lookalike domains (paypa1), artificial urgency (account suspended), and raw IP links (192.168.x.x).

• Expected Outcome:

An automated scanner that calculates an accurate Risk Score (0–100), outputs immediate verdicts (SAFE or CRITICAL), and guides users with prevention advice.

SECTION 3
Problem Statement - Why This Project Matters

What Problem?

Cyber adversaries exploit human psychology rather than software bugs.

They create fake emails that visually mimic real banks, universities, or services to manipulate users into surrendering passwords and credit cards.

Who Faces It?

  • College Students: Targeted with fake scholarships, exams, or campus jobs.
  • Non-Tech Users: Unable to spot tiny spelling tricks like paypa1.com.
  • College Labs: Lack expensive enterprise security gateways.

Why It Matters?

  • Financial Loss: Accounts drained in minutes.
  • Credential Theft: University accounts compromised.
  • Awareness: A simple C tool teaches students how phishing works internally.
SECTION 4
Literature Survey (5 to 6 Papers Analyzed)
Paper 1: Bergholz et al. (2010) - Model-Based NLP & Markov Chains
Solution: Statistical text analysis of deceptive phrasing.
Limitation: High computation; fails on short/image-only emails.
Paper 2: Basnet et al. (2012) - Machine Learning (SVM, Naive Bayes)
Solution: Trained ML models on 16 email structural features.
Limitation: Complex black-box; vulnerable to evasion tricks.
Paper 3: Sheng et al. (2009) - URL Blacklists (PhishTank, Google)
Solution: Database of known malicious links.
Limitation: Zero protection on fresh links (4-12 hr delay).
Paper 4: Almomani et al. (2013) - Email Filtering Survey (SPF/DKIM)
Solution: Cryptographic DNS authentication checks.
Limitation: Display Name spoofing still bypasses basic SPF.
Paper 5 [BASE PAPER]: Fette et al. (2007) - PILFER Framework
Solution: Structural feature extraction (IP links, forms, HTML).
Limitation: False alarms on legitimate newsletters with many links.
Paper 6: Marchal et al. (2016) - Lexical Brand Target Matching
Solution: Brand name vs registered domain comparison.
Limitation: Heavy browser extension latency & DB lookups.

Visual Anatomy of a Phishing Email

The 4 Core Security Checks in C:

1. Lookalike Sender (+35 pts): Flags deceptive spellings like paypa1.com.

2. Panic Subject (+25 pts): Flags urgency words like "URGENT" or "Suspended".

3. Raw IP Link (+25 pts): Real companies don't use raw IPs (192.168.1.50).

4. Credential Demand (+30 pts): Asking for passwords, OTPs, or credit cards.

Verdict: Total score $\ge 50$ triggers [CRITICAL PHISHING ALERT]!

SECTION 5
Proposed Work (Base Paper & C Implementation)

Base Paper:

Fette et al. (2007) - "Learning to Detect Phishing Emails" (PILFER), IEEE / ACM WWW.

How We Adapted It in Beginner C:

  • Converted heavy formulas into 4 simple if-else string rules.
  • Uses standard beginner C functions: fgets(), strstr(), tolower().
  • Zero setup or external dependencies; runs natively on GCC / VS Code.
// simple_phishguard.c (Student C Code)
#include <stdio.h>
#include <string.h>

int main() {
    char sender[100], subject[150], body[500];
    int score = 0;

    // CHECK 1: Fake Sender (paypa1, .xyz)
    if (strstr(sender, "paypa1")) score += 35;

    // CHECK 2: Panic Subject (urgent, suspended)
    if (strstr(subject, "urgent")) score += 25;

    // CHECK 3: Raw IP Link (http://192.)
    if (strstr(body, "http://192.")) score += 25;

    // CHECK 4: Credential Demand (password, card)
    if (strstr(body, "password")) score += 30;

    if (score >= 50) printf("CRITICAL PHISHING!");
    else printf("SAFE EMAIL");
    return 0;
}
